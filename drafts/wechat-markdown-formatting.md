# 公众号排版一粘就散？四个断裂点与一套可复现的修法

你在本地写好 Markdown：标题层级清楚、代码块带底色、列表对齐。全选复制，粘进公众号后台，字号变回默认值，行距挤在一起，二级标题和正文长得一模一样。

问题不在你写得不对，而在两道工序之间缺一个接口：从 Markdown 到渲染器，再从渲染器到公众号编辑器。这篇文章把这条链上的四个断裂点拆开，每个都给一个能验证的修法。

## 一、结论先行：公众号编辑器只吃内联样式

公众号后台的粘贴过滤会丢掉 `<style>` 块、`<link>` 外链样式表和标签上的 `class` 属性，只留下标签自身的 `style` 属性。换句话说，一份好看的 CSS 在这里没有落点。

这解释了为什么很多排版工具最后都变成"行内样式生成器"：不是它们偷懒，是能穿过过滤层的通道只有那一根。

## 二、断裂点一：样式在粘贴那一步就被剥掉

依赖 class 的方案失效后，浏览器默认样式接管：h2 掉成和正文同字号的粗体，段落间距归零，列表缩进错位。你在本地看到的和读者看到的，是两份不同的文档。

修法：渲染阶段直接把样式写进 `style` 属性，一个字都不留给外部样式表。代价是 HTML 体积变大——一千五百字左右的文章，行内样式版通常在几十 KB。

换来的确定性是值得的：粘贴即所见，不再依赖读者的阅读器，也不再依赖编辑器版本。

验证方式很机械：渲染完成后逐个检查块级标签是否带 `style`，缺一个就不算通过。人工肉眼比对不可靠，标签一多必然漏看。

## 三、断裂点二：段落没有长度上限

手机一屏大约五到七行，一行十八到二十二个汉字。一个三百字的段落就是十几行连续文字，读者看不到"下一步往哪看"，会直接划走。

我给自己定的阈值是单段不超过一百八十字，超了就拆。这不是美学要求，而是给读者一个规律的重启点：每六到八行遇到一次换行、一个判断、一个动作。

拆段有三种具体手法：

- 一段只放一个判断，第二个判断另起一段
- 数据单独成段，前后各留一句解释
- 转折词之前断开，"但是""所以""反过来"都是天然的分段点

拆完回头看，段落变短了，信息并没有少，反而更容易被复述——读者能记住的是判断，不是句子。

## 四、断裂点三：标题和摘要在列表页被截断

读者第一次看到你的文章，几乎都不是在正文页：公众号列表、转发卡片、搜索结果，显示的都是一行标题加一段摘要。

标题的可用空间比大多数人以为的窄。我的做法是把标题压到六十四字以内（实际写作目标十八到二十四个字），并把"这篇讲什么对象、有什么用"塞进前十个字。

摘要在卡片上只露一两行，所以第一句就得是结论，不要用"最近有很多人问我"开场。

一个自检动作：把标题单独念出来，如果听不出对象和收益，说明它只在全文语境里成立，换个场合就不成立。

## 五、断裂点四：发布前没有门禁

大多数翻车不是写不好，是没人检查。人对自己写的字有免疫力——读了十遍也看不出那个错字，更看不出超长段落和被剥掉的样式。

我把检查拆成两级，只有硬错误会阻断发布：

| 级别 | 检查项 | 处理 |
| --- | --- | --- |
| 硬错误 | 残留脚本、外链样式、内联样式表、class 属性 | 阻断 |
| 硬错误 | 正文过短（不足六百汉字）、没有小节 | 阻断 |
| 硬错误 | 标题或摘要超出长度上限 | 阻断 |
| 警告 | 单段超过一百八十字 | 人工判断 |
| 警告 | 承诺性表述、诱导分享的表述 | 人工判断 |

分成两级的理由：承诺性表述有时是引用别人的话，机器不该替你做决定；但样式残留没有歧义，该拦就拦。

## 六、一条可复现的流水线

把上面四件事串起来，就是六步：选题单、正文、渲染、自检、发布、复盘。每一步都落盘，失败能单独重跑，不用从头再来。

```bash
node cli.mjs new    wechat-markdown-formatting
node cli.mjs render drafts/wechat-markdown-formatting.md
node cli.mjs check  drafts/wechat-markdown-formatting.html
node cli.mjs static drafts/wechat-markdown-formatting.html --out docs
node cli.mjs track  data/channels.csv
```

前四条命令就是这篇文章自己的生产流程。`check` 不通过时退出码非零，可以直接接在发布脚本前面当门禁。

发布环节留了两种出口：推公众号草稿箱（需要公众号的 AppID 与 AppSecret），或者生成一个静态站挂到公网。后者适合还没拿到接口权限的人，链接可以直接发给读者。

## 七、结尾

排版不是审美问题，是接口问题。样式写进标签、段落切到能一口气读完、标题前十字说清对象和收益、发布前有一道会拦人的门禁——这四件事做完，读者才有机会看到第二屏。
